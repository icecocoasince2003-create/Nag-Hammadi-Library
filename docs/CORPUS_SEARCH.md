# コーパスの形態素・正規表現検索

`search.html` の〈検索〉では、従来の〈単語〉検索に加えて、〈品詞列〉と〈詳細式〉を選択できます。〈単語〉はレンマ・語形・語義を検索し、レンマごとに集計します。〈品詞列〉と〈詳細式〉は一致した形態素の並びを文脈付きで表示し、元の本文へ移動できます。

〈品詞列〉と〈詳細式〉は、入力が0.5秒止まると自動で検索します（書きかけの式をそのつどエラーにしないため、〈単語〉より長く待ちます）。Enter キーか〈検索〉ボタンを押すと、すぐに検索します。

## 品詞の並びを探す

〈品詞列〉で、品詞タグを空白で区切ります。

```text
ART N
ART N V
```

`ART N` は「冠詞のすぐ後に名詞がある箇所」です。`N` と `NPROP` は別のタグです。タグは左の〈品詞〉一覧でも確認できます。形態素の順番は入力順のまま照合します。

検索の単位は TEI の各 `<w>`（形態素）です。正書法上の単語をまとめる `<phy>` の境界をまたいで検索できます。各 `<s>` と証本の境界をまたぐ一致は返しません。

`<s>` の中に欠損（`<gap>`）があるときは、その前後も別々に扱い、欠損をまたぐ一致は返しません。失われた本文の量が分からず、前後の語が隣り合っていたとも、何形態素離れていたとも言えないためです。用例の文脈には、欠損の位置を `[…]` で示します。

## 詳細式

[ANNIS Query Language (AQL)](https://korpling.github.io/ANNIS/4.5/user-guide/aql/word-forms.html) の、注釈値と先行関係を用いる記法を参考にした部分実装です。ANNIS 本体や AQL 全体を実装するものではありません。

| 目的 | 詳細式 |
| --- | --- |
| 名詞 | `pos="N"` |
| 冠詞の直後に名詞 | `pos="ART" . pos="N"` |
| 冠詞の1〜3形態素後に名詞 | `pos="ART" .1,3 pos="N"` |
| 冠詞のちょうど2形態素後に名詞 | `pos="ART" .2 pos="N"` |
| 特定レンマの直後に名詞 | `lemma="ⲡ" . pos="N"` |
| 語形の完全一致 | `tok="ⲣⲱⲙⲉ"` |
| 名詞または固有名詞 | `pos=/N.*/` |
| 語形の一部を正規表現で指定 | `tok=/.*ⲣⲱⲙ.*/` |
| 任意の1形態素を挟む | `pos="ART" . tok . pos="N"` |

距離 `1` は隣接です。`.1,3` は間に0〜2形態素を許容し、`.2` は間にちょうど1形態素を置きます。距離の上下限は1〜1000です。各節の条件を満たす形態素の組み合わせを結果として返すため、同じ開始位置から複数の一致が返る場合があります。

| 注釈名 | 対象 |
| --- | --- |
| `tok` / `form` | `<w>` の語形 |
| `lemma` | `<w @lemma>` |
| `pos` / `type` | `<w @type>` の品詞タグ |
| `msd` | `<w @msd>` の形態情報（付与されている場合） |

値は `="..."` または `=/.../` で指定します。文字列は JSON の文字列記法に従い、引用符は `\"`、バックスラッシュは `\\` と書きます。正規表現内の `/` は `\/` と書きます。条件を付けない `tok` は任意の1形態素に一致します。

`&`、`|`、`#1` による参照、包含・支配などの構造演算子、`.*` による無制限距離はサポートしません（距離に上限を付けて `.1,1000` のように書きます）。非対応の式や不正な正規表現はエラーとして表示します。エラーは画面の表示言語（日・英・仏）で、式の何文字目に問題があるかとともに表示します。

## 正規表現の照合

ANNIS と同様、正規表現は**注釈値全体**に一致する必要があります。`pos=/N/` は `N` にのみ一致し、`NPROP` には一致しません。一部を探すには `.*` を明示します。

正規表現は、それだけで完結した式である必要があります。`pos=/N)|(V/` のように括弧の対応が取れていない式は、全体一致の枠を外れてしまうためエラーにします。

正規表現の処理系はブラウザーの JavaScript（Unicode モード）です。ANNIS の Rust 正規表現との完全互換はありません。大文字・小文字を区別し、検索する注釈値は NFC に正規化します。上線などの合成記号は除去しません。例えば `tok=/ⲣⲱⲙⲉ/` は上線を含む語形には一致しません。正規表現の外側に `i` などのフラグを付ける記法は使用できません。

文字列による語形・レンマの照合（`tok="..."`、`lemma="..."`）は、従来の単語検索と同じく、大文字・小文字と上線などの合成記号を無視します。品詞タグと `msd` の文字列は大文字・小文字を区別して完全一致します。正規表現の内容は書き換えません。

## 絞り込み・共有

左の〈文書〉で対象証本を選びます。〈品詞〉で除外した品詞は、一致する形態素として返しません。距離を数える際には除外した形態素も元の位置に残します。例えば `ART ADV N` から `ADV` を除外しても、`ART N` の隣接一致にはなりません。`.2` を指定した場合には、間の `ADV` は距離に含まれます。

検索条件は URL に保存されるため、再読み込みやリンクの共有で同じ条件を開けます（`kind=pos` が品詞列、`kind=aql` が詳細式）。検索結果のハイライトは条件に一致した各形態素を示し、距離条件で間に入る形態素はハイライトしません。文脈として、一致した各形態素の前後6形態素を表示します。距離を大きく取った式では、一致した形態素どうしの間を「…」で省きます。

〈CSV で保存〉は取得済みの全用例を出力します。証本ID・セグメントID・一致した語形・レンマ・品詞・セグメント内の形態素位置（1始まり）・本文リンク（絶対 URL。ビュワーのない未注釈の本文では空欄）を含みます。〈さらに表示〉で画面に追加する前の用例も含まれます。

## 未注釈の本文（ナグ・ハマディ写本 全文）を検索する

左の〈未注釈の本文〉を開くと、ナグ・ハマディ写本 I–XIII の本文（56文書・約24万語）が写本ごとに並びます。文書、写本、または〈すべて選択〉にチェックを入れると、その文書の本文を読み込んで検索・統計の対象に加えます。既定では選択も読み込みもしません（読み込むのは選んだ文書の XML だけです）。

この本文には品詞・レンマ・訳が付いていません。検索では次のように扱います。

| 項目 | 未注釈の本文での値 | 使い方 |
| --- | --- | --- |
| 語形 `tok` | 本文の語形 | `tok="ⲛⲟⲩⲧⲉ"`、`tok=/.*ⲯⲩⲭⲏ.*/`、単語検索の〈語形〉 |
| レンマ `lemma` | 語形と同じ | 語形として一致します（見出し語にはまとまりません） |
| 品詞 `pos` | すべて `X`（未注） | `pos="N"` などの条件や〈品詞列〉には一致しません |

- **語の区切りは元ファイルのままです。** 接頭辞や冠詞が分かれている箇所と、つながっている箇所があります（`ⲧ ⲉⲯⲩⲭⲏ`、`ⲧⲯⲩⲭⲏ`）。語の一部を探すときは `tok=/.*ⲯⲩⲭⲏ.*/` のように前後を `.*` で受けてください。隣り合う語の並びは `tok="ⲡ" . tok="ⲛⲟⲩⲧⲉ"` のように書けます。
- **欠損の情報は行・頁単位の注記だけです。** 元ファイルに注記のあった欠損は `<gap>` になっており、検索はそこをまたぎません。それより小さい欠損や復元の区別（角括弧・下点）は元ファイルになく、本文にも入っていません。
- **本文へのリンクはありません。** 文書を表示するビュワーがまだないので、用例には証本と § 番号（文書内の通し番号。`tsv/` の `seq` 列）だけを示します。
- **III,3 と VI,5 は注釈つきの版が別にあります**（『祝福されたエウグノストス』と『国家』）。〈すべて選択〉と写本ごとの選択は、注釈つきの版が選ばれている間、この2つの未注釈の版を対象から外します。個別に選ぶことはでき、その場合は同じ本文を二重に数えている旨を表示します。
- **作業用の本文です。** 校訂本との照合は済んでおらず、元ファイルで落ちていた ⲍ・ⲯ を補った語が 744 あります（うち 42 語は確度 B）。内容と要確認の箇所は [`source/nhc_fulltext_split/README_ja.md`](../source/nhc_fulltext_split/README_ja.md) にあります。

選択は URL の `w=` に証本 ID で保存されます（`w=wit-rep,wit-III,wit-V,wit-II-6`）。未注釈の文書の証本 ID は `wit-` ＋写本番号と文書番号です（II,6 → `wit-II-6`、XI,2a → `wit-XI-2a`）。`?doc=II-6` と書くと、その文書だけを選んだ状態で開きます。

文書の一覧（題名・略号・語数）は `data/catalog.xml` の `<bibl subtype="unannotated">` にあり、`scripts/sync_nhc_catalog.py` が `source/nhc_fulltext_split/` から書き出します。

## 上限

- 結果は最大2000件です。上限で打ち切った場合はその旨を表示し、CSVにも先頭2000件を出力します。
- 式は最大4096文字・16形態素、距離は最大1000です。
- 距離の範囲が広く、候補の組み合わせが膨大になる検索は、処理量の上限（組み合わせの照合 200万回）で停止します。数えるのは組み合わせの照合だけで、各形態素を条件に当てる走査は数えません。コーパスが大きくなっても、条件の絞られた式が上限に掛かることはありません。
- 正規表現は Web Worker 内で実行します。検索が3秒を超えた場合は Worker ごと停止するため、検索画面の操作を続けられます。3秒は Worker が本文を受け取ってから数えます（スクリプトの取得や本文の受け渡しの時間は含めません）。

上限で止まった場合は、条件を増やす・距離を狭める・文書を絞り込むなどして検索し直せます。

Worker は1つを使い回し、本文を渡すのは起動時の1回だけです。実行中の検索を止める必要があるとき（別の式で検索し直した、3秒を超えた）だけ作り直します。

## 開発時の検証

検索エンジンは `assets/corpus-query.js`（式の解釈と照合。ブラウザーと Node.js の両方で動きます）、Worker は `assets/corpus-search-worker.js`、画面は `search.html` です。エラー文の三言語の文面は `search.html` の `QERR` にあり、キーは `corpus-query.js` が返すエラーの `detail` です。上限値を変えるときは `corpus-query.js` の `LIMITS` と `QERR` の文面を揃えてください。

Node.js がある環境で次を実行します。追加パッケージは不要です。

```sh
node --test tests/corpus-query.test.cjs
```

検索画面の確認には、リポジトリ直下を HTTP サーバーで配信します。

```sh
python3 -m http.server 8000
```

`http://localhost:8000/search.html` で単語検索、品詞列、詳細式、証本・品詞の絞り込み、検索URLの再読み込み、不正な式のエラー、統計タブへの切り替えを確認します。
