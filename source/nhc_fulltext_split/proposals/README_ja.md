## 1. 頁・行の区切り（`scripts/insert_breaks.py`）

手順の説明は、リポジトリの `README.md` の「写本の頁・行の区切りを入れる」にあります。ここには決めた理由だけを書きます。

- **入力の形。** TSV の列は `doc`・`seg_id`・`w`・`type`（`pb` か `lb`）・`n` が必須で、`char`（語の途中で切れるとき、
  何文字目の前か）・`place`（欠損 `<gap>` の前に入れるとき `before-gap`）・`phr`・`form`（打ち間違いを見つけるための
  確認用。書けばスクリプトが実際の語群番号・語形と照合する）・`note` が任意です。`doc` は `data/catalog.xml` の
  `doc-…` から `doc-` を除いたもの（`II-2`・`eugnostos` など）で、ファイルはカタログの `<ref type="xml">` で決まります。
  語の位置を「何番目の `<w>`」で表すのは、セグメントの中で一意に決まり、語群を直しても変わらないためです（`<w>` を
  分けたりつないだりしない限り）。
- **書き方は `data/republic_tei.xml` に合わせました。** 改頁のあとの最初の行も `lb` として書き（`<pb n="49"/><lb n="1"/>`）、
  `pb` のあとに `lb n="1"` を自動では足しません。頁の途中から始まる文書（ヘッダーの参考値では II,2 は 32 頁 10 行目から）も
  あるためです。
  語群の最初の形態素の前なら `<phr>` の前、語群の途中なら `<phr>` の中、語の途中なら `<w>` の中に `break="no"` 付きで
  入れます。セグメントの最初の語の前の区切りは `<s>` の中の先頭です。
- **確かめたこと。** `data/republic_tei.xml` の 113 個の区切りをすべて外した複製に、同じ位置を TSV にして入れ直すと、
  113 個とも元と同じ位置・同じ順に戻りました（違いは、元のファイルで字下げがずれていた 7 行の空白だけ）。複製の II,2・
  V,2（語群なし）・V,4（末尾が欠損のセグメント）・エウグノストスで、語群のあいだ・語群の中・語の中・`<supplied>`
  （復元した字）の前後・欠損の前後に入れ、`check_tei.py` と TEI のスキーマ（tei_all.rng、P5 4.3.0）で妥当なこと、
  同じ TSV で 2 回目は何も変わらないこと、わざと誤りを入れた行（存在しない文書・セグメント・語、範囲外の `char`、語形・
  語群番号の食い違い、同じ位置の重複、既存の区切りとの衝突など 17 通り）がどれも止まって何も書き込まないことを確かめました。
  わざと壊した結果（文字・属性・ID の変更、区切りの位置のずれ）は、書き込む前の検証がどれも見つけます。
- **試験用のファイル**（`tests/fixtures/`。どれも試験用の値で、実際の頁・行ではない。ヘッダーの `<notesStmt>` に明記）:
  `reader_breaks_draft.xml`（II,2 の §1–8。57 個）、`reader_breaks_plain.xml`（V,2 の §1–6。23 個）、
  `eugnostos_breaks.xml`（`data/eugnostos_tei.xml` の複製。証本 III の最初の 5 セグメントに 27 個）。それぞれ同じ名前の
  TSV からこのスクリプトで入れたものです。TSV の `doc` は `test-II-2`・`test-V-2`・`test-eugnostos` で、カタログに無い名前に
  してあるので、`--file` を付けずに実行しても本物のファイルには入りません。

**実データに入れる前に直す必要があるもの。** `source/nhc_fulltext_split/scripts/verify_tei.py`（§10・§11 の検証）は、
`<s>`・`<phr>`・`<w>` の中に `<pb>`・`<lb>` があると「想定外の要素」として失敗します（区切りを入れた複製で確かめた）。
`<s>`・`<phr>` の子をたどるところで区切りの要素（`pb`・`lb`・`cb`・`milestone`）を読み飛ばし、`<w>` の中では
`<supplied>` 以外に `<lb>`・`<pb>` も認める（語形は `itertext()` で読む）ように直してから、区切りを入れてください。
このスクリプトは今回の作業の範囲外なので直していません。`check_tei.py`・`build_parallels.py`・`sync_nhc_catalog.py` は、
区切りがあっても今までどおり動きます（リポジトリの複製で II,2・III,4・V,1・エウグノストスに区切りを入れて実行し、
並行箇所とカタログの結果が入れる前と同じだった）。検索ページは `<w>` の `textContent` を読むので、語の途中の `<lb/>` は
語形に影響しません（コードを読んで確かめた）。

### 2.2 語録の番号をどう表すか（案）

語録の番号は現代の慣例で、元ファイルの行（`<s>`、サイトの §）とは別のものです。§ と語録の境目は合わず（上のとおり 14 の
語録がセグメントをまたぎ、§1 には序文と語録 1–13 と 14 の前半、§15 には語録 44 の終わりから 112 の始まりまでが入っている）、セグメントを
分け直すかどうか（§3・§4）とも別に決められるので、本文の構造とは別の層として持つのがよいと考えます。候補は 2 つです。

**案 A（勧める）: 区切りの印 `<milestone unit="saying" n="12"/>`**

語録の始まりの位置に空要素を置きます。置き方は頁・行の `<pb>`・`<lb>` と同じ（語群の前、セグメントの最初なら `<s>` の
中の先頭）。ヘッダーの `<encodingDesc>` に `<refsDecl><refState unit="saying"/></refsDecl>` を足すと、TEI のやり方で
「語録番号による参照」を宣言できます（`<milestone>` を `<s>` の中・`<phr>` の中に置いたもの、`<refState>` を足したものが
TEI のスキーマで妥当なことを複製で確かめた）。序文は `<milestone unit="saying" n="0"/>` か `unit="prologue"` で示します
（どちらにするかは決めてください）。

- 利点: いまの `<s>` とその `xml:id` に手を付けずに足せる。語録がセグメントをまたいでも、セグメントの途中で始まっても
  問題ない。§3・§4 でセグメントを分け直す前でも後でも置ける。頁・行と同じ仕組みなので、`insert_breaks.py` を少し広げれば
  （`type` に `milestone` と `unit` を足す）同じ TSV の形で入れられる。検索ページ・カタログの件数・`check_tei.py` には
  影響しない。
- 欠点: 語録の「範囲」は要素として無く、次の印までとして計算する（ビュワーは頁・行と同じく、印を本文の順にたどる）。
  `<s>` の中に置くので、`verify_tei.py` は `pb`・`lb` と同じく読み飛ばすように直す必要がある。語群の途中から始まる 6 つは、
  先に `<phr>` を直さないと語群の中に印が入る（TEI としては妥当だが、語群の誤りを残すことになる）。

**案 B: 語録ごとの区分 `<div type="saying" n="12">`**

- 利点: 語録 1 つが 1 つの要素になり、範囲がはっきりする。「Thomas 12」をそのまま要素で指せる（`xml:id` を付ければ
  ポインタでも指せる）。
- 欠点: TEI では `<div>` を `<ab>`・`<s>` の中に置けない（複製で確かめた: `<ab>` の中の `<div>` はスキーマ違反）。
  `<div type="tractate">` の中を `<div type="saying">` ＞ `<ab>` ＞ `<s>` の形に組み替えることになり、そのためには語録の
  始まり 114 か所すべて（§2 以降のセグメントはどれも語録の始まりから始まらないので、§1 の 14 か所、§15 の 68 か所を含む
  すべて）で、先にセグメントを分ける必要がある（§4。新しい `xml:id` が 100 以上でき、元の id で指していた箇所は最初の
  部分だけを指すようになる）。`verify_tei.py`（`div` の子は `head` と `ab` だけ、と確かめている）は直す必要があり、
  本文ビュワーの読み込みも確かめが要る（検索ページは `<text>` の子孫の `<s>` を読むので、入れ子が深くなっても読める。
  コードで確かめた）。語群の誤りで語群の途中から始まる語録は、`<phr>` を直さないと分けられない。

**勧めるのは案 A です。** いまのセグメント・ID・リンク・投稿を壊さずに足せて、頁・行と同じ道具で扱えるためです。
将来、すべての語録の始まりでセグメントを分けることになれば、そのときに印から `<div>` を機械的に作ることもできます。

**引用。** いまの引用は「NHC II,2 §3」（§ は元ファイルの行）で、これは変えずに残します。語録の層を入れたら、
本文ビュワーの引用に「トマス 12」（Thomas 12）を添える形（例「NHC II,2 §1（トマス 12）」、頁・行が入っていれば
「NHC II 頁,行–行（トマス 12）」）を提案します。§ の番号と語録番号は別の数なので、混同しないように表示を分けます。
リンクは `#seg-…`（セグメント）とは別に `#saying-12` のような形を足すのがよいと思います（決めるのはビュワーの側）。
既存の `xml:id` は、案 A では 1 つも変わらず、案 B では多くのセグメントを分けることになります。

## 3. 長いセグメントの分け目の候補（`long_segment_breaks.tsv`）

### 3.1 300 形態素を超えるセグメント（56 文書すべてで数え直した）

予想どおり 17 個で、数・位置とも違いはありませんでした（`data/` の 2 ファイルは最大でエウグノストス III の 122、

## 4. セグメントの分け方（`scripts/split_segments.py`）と § の番号

### 4.1 規則（案）

- **最初の部分は元の `xml:id` と `@n` のまま。** 続く部分の `xml:id` は「元の id ＋ `_a`、`_b`、…」（z のあとは `_aa`、
  `_ab`…）、`@n` は「元の n ＋ `a`、`b`、…」で、id と同じ記号を使います（`II-7503917` を 3 つに分けると
  `II-7503917`（§15）・`II-7503917_a`（§15a）・`II-7503917_b`（§15b））。元の id は「写本番号-行 ID（_開始トークン位置）」の
  形で、末尾は数字なので、`_a` のような英字の付いた id とはぶつかりません。
- 分けるのは語群の境目だけ（語群の無い 17 文書ではどの語の前でもよい）。分け目の直前の `<pb>`・`<lb>` は新しい
  セグメントの先頭に入り、直前の `<gap>` は前のセグメントに残ります（`place=before-gap` で新しい方に入れられる）。
- 新しい `<s>` には `xml:id` と `n` だけを付けます。元の `<s>` にほかの属性（エウグノストスの `type="incipit"`・
  `corresp="#wit-V"` など）があれば報告します（写さない）。
- 入力 TSV の列は `doc`・`seg_id`・`w`（新しいセグメントの最初の `<w>`）が必須、`place`・`phr`・`form`・`note` が任意。
  `long_segment_breaks.tsv`・`thomas_sayings.tsv` は、そのまま渡せます（2026-11-23 から。列「状態」のある表は提案の表として読み、
  状態が「承認」か「修正して承認」の行だけを当てはめる。「修正した位置」があればそちらを使い、`thomas_sayings.tsv` では種別が
  「語録の始まり」の行だけを分け目にし、文書は `--doc II-2` で渡す）。判断は確認作業の画面 `review.html` で行い、書き出した表を
  コミットします（リポジトリの README「確認作業の画面」）。

### 4.2 § の番号の付け方

| 案 | 例（§15 を 3 つに） | 既存の引用「NHC II,2 §15」 | 後ろの § | 評価 |
|---|---|---|---|---|
| **a. 枝番（勧める）** | §15・§15a・§15b | 同じ位置（元の §15 の始まり）を指す。ただし §15 は最初の部分だけになる | 変わらない（§16 は §16 のまま） | id の記号と一致し、元の番号がすべて残る |
| b. 振り直し | §15・§16・§17、元の §16 は §18 | 位置は同じだが、元の §16 以降の引用がすべてずれる | すべて変わる | 引用・投稿の表示が食い違うので勧めない |
| c. 小数 | §15・§15.1・§15.2 | a と同じ | 変わらない | 「15.1」が頁・行（32,10）や小数と紛れやすい |

**勧めるのは a です。** 分けたあとに元の §15 全体を指すときは「§15–15b」と書けます。サイトの表示（`§`＋`@n`）は
文字列なので、`15a` のような値でもそのまま出ます（本文ビュワー・エウグノストスのビュワー・検索ページの用例の場所を
確かめた）。

### 4.3 分けたあとに変わること

- **元の id へのリンク**（`#seg-II-7503917`、投稿・ブックマークの `seg_id`、検索結果のリンク、HOME の `VI-7#seg-VI-7508309`
  のような固定リンク）は、分けたあとも開けます。開くのは最初の部分で、元のセグメントの始まりと同じ位置です。リンクの
  多くは「その箇所の始まり」を指しているので、**これで差し支えないと考えます。** ただし、元のセグメントの後ろの方の
  内容について書かれた投稿は、続きの部分（`_a` 以降）を見ないと話が合わなくなります。ビュワーでは、元の id で開いたときに
  続きの部分（`<id>_a`、`<id>_b`…）も一緒に強調するか、「この § は §15–15b に分けました」と添えるのがよいと思います
  （ビュワーの側の作業）。
- **検索ページ**の用例の場所は §15a のように新しい番号で出て、リンクも新しい部分を指します。統計のセグメント数は増えます。
- **カタログ**（`data/catalog.xml`）のセグメント数は `python3 scripts/sync_nhc_catalog.py --write` で直ります。各 TEI の

  id が「写本番号-行 ID（_数字）」の形であることを確かめているので、分けると失敗します（複製で確かめた）。続きの部分
  （`<元の id>_<英字>`）を前の部分につないでから比べるように直す必要があります。
- **id を指しているもの**（スクリプトが一覧を出す。変えない）: `data/parallels.xml` の `<link>`（いまはエウグノストス III,3・

  書いてある）、このフォルダの 2 つの表。分けたあと、位置が元のセグメントの中の番号で書かれているものは読み替えが要ります。
