### ⲍ・ⲯ の復元について

元ファイルには ⲍ が 1 つもなく、ⲯ も本来の位置には 1 つもない（ⲯⲩⲭⲏ → `ⲩⲭⲏ`、ⲃⲁⲡⲧⲓⲍⲉ → `ⲃⲁⲡⲧⲓⲉ`、ⲁⲡⲟⲕⲁⲗⲩⲯⲓⲥ → `ⲁⲡⲟⲕⲁⲗⲩⲓⲥ`）。どこで落ちたかの印は残っていないので、次の手順で戻した。

1. ⲍ か ⲯ を含む語形を集めた（Coptic Scriptorium の coptic-nlp に入っている語彙表とサイトの `lexicon.csv` にある約 1,700 形に、NHC に出る固有名や数詞を足したもの）。
2. それぞれから ⲍ・ⲯ を抜いた形を本文から探した。空白は無視して探すので、`ⲥⲩⲛ ⲩⲅⲟⲥ` のように途中で切れている語も拾える。

**編集注記の残骸について。** 元ファイルは「大文字＝ギリシア文字由来の字、小文字の s f k h j g t ＝ ϣ ϥ ϧ ϩ ϫ ϭ ϯ」という翻字から変換されたものとみられる。英語の編集注記も一緒に変換され、この 7 文字と大文字だけが残った。例: "lines missing" → `ϣ ϣϣϭ`、"Lines lacking" → `ⲗϣ ϧϭ`、"Pages …" → `ⲡϭ ϣ …`、"APPROXIMATELY n LINES ARE MISSING" → `ⲁ ⲡⲡⲣⲟⲭⲓⲙⲁⲧⲉⲗ ⲗⲓⲛⲉⲥ ⲁ ⲣ ⲉ ⲙⲓⲥⲥⲓⲛⲅ`。コプト語としては成り立たない並びで（ϧ はこの残骸の中にしか出てこない）、行や頁の欠損を示す注記なので `[...]` に置き換えた。`[...]` が多いのは X（55）、IX,3（37）、IX,1（31）、XI の各文書、VIII,1（18）。

2. **欠損と復元の情報がない。** 角括弧、下点、上線、句読点、頁・行番号は元ファイルに入っていない。復元された文字と現存する文字の区別はつかない。断片的な写本では、欠損をはさんだ前後の文字がそのまま詰めて並んでいるとみられる行がある（例: IV,1 の奥書表題が `ⲕⲁⲧⲁ ⲓⲱⲏⲛ ⲛ ⲁⲡⲟⲕⲣⲩⲫⲟⲛ`。II,1 の同じ表題は `ⲕⲁⲧⲁ ⲓⲱϩⲁⲛⲛⲏⲛ …`）。`[...]` が示すのは元ファイルに注記があった行・頁単位の欠損だけ。
3. **語の区切りは元ファイルのまま。** 空白は形態素解析器の出力らしく、校訂本の分かち書きとは一致しない（`ⲡ ⲉⲩⲁⲅⲅⲉⲗⲓⲟⲛ ⲛⲧ ⲙⲏⲉ`）。断片的な箇所では 1 文字ずつに分かれている。解析器は ⲍ・ⲯ が落ちたあとの文字列にかけられているので、戻した語のまわりでは切れ目がずれていることがある（§3）。
4. **レコードの区切りも元ファイルの行のまま。** 中央値は 11 トークンだが、49 レコードは 200 トークンを超え、最大は 3,515 トークン（II,2 の 15 番目）。II,1、II,2、XI,1、XI,2 は少数の長大な行でできている（II,2『トマスによる福音書』は 18 レコード）。
5. **I,1『使徒パウロの祈り』は元ファイルに含まれていない。** I,2 から始まる。
6. **本文中の小見出しは `text` のまま。** XIII,1 の `ⲡⲁ ⲧ ϩⲓⲙⲁⲣⲙⲉⲛⲏ ⲃ` など。`title`／`subscript` を付けたのは文書全体の表題だけ。

## 6. 文書の境目について

- **並び順は写本順**（I → II → III → IV → … → XIII）。境目の多くは元ファイルの行の途中にあり、奥書表題、冒頭表題、書き出しの定型句を手がかりに決めた。`build.py` の中では「行 ID ＋ その行の中の文字列」で指定してある。
- **元ファイルに入っていた見出しとの対応**

| 見出し（行） | 結果 |
|---|---|
| `1,2--The Apocryphon of James--`（1） | I,2 の開始位置と一致 |
| `1,3` `1,4` `1,5`（384、1119、1132） | 行の途中に入れてあった位置と、こちらで決めた境目が 3 つとも一致 |
| `2,1--The Apocryphon of John`（5666） | この位置から始まるのは **IV,1**（直前が III,5 の奥書表題、直後が IV,2）。II,1 は I,5 の直後、ID 7503827 の 3 語目から始まる |
| `2,2 Two Sets of Names`（5779） | IV,1 の途中。文書の境目ではないので分けていない |
| `--6, Republic,Pluto--`（8063） | VI,5 の開始位置と一致 |

- **XI,2 は 6 つに分けた。** 本体（XI,2）と、塗油・洗礼 A・洗礼 B・聖餐 A・聖餐 B（XI,2a–2e）。元ファイルではこの 6 つとアロゲネース冒頭が 1 行（ID 7512572）に入っている。まとめて扱うなら `nhc_all.tsv` で `unit` が `XI,2` で始まるものを連結すればよい。
- **確度が低い境目**
  - XII,2 と XII,3: 断片どうしで決め手がない。`ⲡ ⲉⲧ ϥ ⲉⲩⲇⲟⲕⲉⲓ` の直後で切った。
  - VII,4 と VII,5: シルウァノスのコロフォン末尾の `ⲧ ⲩ` がどちらに付くか不明。VII,4 側に入れた。
  - IX,3 の末尾（ID 7512181 以降の 47 行）: 数文字ずつの断片が続く。写本 IX の未同定断片が混じっている可能性があるが、区別できないので IX,3 に入れたまま。
  - X: 奥書表題 `ⲙⲁⲣⲥⲁⲛⲏⲥ` より後ろの 3 レコードは未配置断片とみて `fragment` にした。

## 7. 要確認の箇所

- **確度 B で戻した 42 語。** 校訂本・翻訳で知られている読みを当てたもの。`restored_letters.tsv` で `confidence` が B の行。「英訳で確認」としたもの（31 語）は、Early Christian Writings に載っているその文書の英訳で、同じ位置に z・ps の入った綴りになっていることを確かめた（2026-11-17 閲覧。`earlychristianwritings.com/text/` の `apocryphonjohn.html`、`eighthninth.html`、`hypsiphrone.html`、`zostrianos.html`、`marsanes.html`）。コプト語の校訂本とは照合していない。
  - II,1・IV,1 の天使名: `ⲁⲥⲧⲣⲱⲯ`、`ⲍⲁⲃⲉⲇⲱ`、`ⲯⲏⲣⲏⲙ`、`ⲇⲓⲟⲗⲓⲙⲟⲇⲣⲁⲍⲁ`、`ⲁⲙⲓⲱⲣⲯ`（各 2）と II,1 の `ⲁⲁⲧⲟⲓⲙⲉⲛⲯⲏⲫⲉⲓ`（計 11）。英訳で確認（Astrops、Zabedo、Pserem、Diolimodraza、Amiorps、Atoimenpsephei）。最後の名前は英訳では A が 1 つだが、元ファイルは II,1（`ⲁ ⲁⲧⲟⲓⲙⲉⲛⲏⲫⲉⲓ`）も IV,1（`ⲁⲁⲧⲟⲓⲙⲉⲛⲫⲏⲫⲉⲓ`）も ⲁ が 2 つなので、II,1 では語頭の ⲁ も名前に含めてつないだ。
  - `ⲓⲉⲥⲥⲉⲩⲥ ⲙⲁⲍⲁⲣⲉⲩⲥ ⲓⲉⲥⲥⲉⲇⲉⲕⲉⲩⲥ` の ⲙⲁⲍⲁⲣⲉⲩⲥ（III,2 ×2、V,5、VIII,1 ×2）。VIII,1 の 2 か所は英訳で確認（Mazareus）。
  - `ⲥⲧⲣⲉⲙⲯⲟⲩⲭⲟⲥ`（III,2、IV,2、VIII,1）、VIII,1 の `ⲍⲱⲅⲉⲛⲉⲑⲗⲟⲥ` と `ⲍⲁⲭⲑⲟⲥ ⲙⲛ ⲓⲁⲭⲑⲟⲥ`（×2）。VIII,1 の 4 語は英訳で確認（Strempsouchos、Zogenethlos、Zachthos）。
  - XI,4 の `ⲫⲁⲓⲛⲱⲯ`（×5）。英訳で確認（Phainops）。
  - VI,6 の `ⲍⲱⲝⲁⲑⲁⲍⲱ` と `ⲍⲱⲍⲁⲍⲱⲑ`（ID 7508173）。英訳で確認（Zoxathazo、Zozazoth）。
  - XI,3 の `ⲍⲍⲁ ⲍⲍⲁ ⲍⲍⲁ`（ID 7512689。元ファイルは `ⲁ ⲁ ⲁ`）。未確認。

  - VII,4（ID 7510541）: 元ファイルは `ⲧⲭⲏ ⲇⲉ ⲉⲧ ⲟ ⲛⲣⲙ ϩⲛⲏⲉⲓ ⲉ ⲡ ⲛⲟⲩⲧⲉ …`。直前の文が `ⲯⲩⲭⲏ ⲛⲓⲙ ⲉⲧ ϩⲏⲛ ⲉ ⲡⲛⲟⲩⲧⲉ` で、この文も女性単数で受けている（`ⲉⲣⲟ ⲥ ⲉ ⲥⲟⲩⲁⲁⲃ`）ので `ⲧⲯⲩⲭⲏ` にした。
- **ⲍ 以外の字が怪しい語。** 元ファイルの字はそのままにして ⲍ だけ入れた: I,5 `ⲥⲧⲁⲇⲓⲁⲍⲉ`（ID 7502284。ⲥⲧⲁⲥⲓⲁⲍⲉ か）、VII,1 `ⲣⲟⲙⲟⲙⲁⲍⲉ`（ID 7509307。ⲣⲟⲛⲟⲙⲁⲍⲉ か）。
- **VII,4 のコロフォン** `ⲓⲭⲑⲩⲥ ⲑⲁⲩⲙⲁ ⲏⲏⲏ ⲁⲙⲏⲭⲁⲛⲟⲛ ⲧ ⲩ`（ID 7510721）: `ⲏⲏⲏ` と `ⲧ ⲩ` の由来が分からない。装飾の転写か注記の残骸の可能性がある。
- **入力ミスとみられる ⲝ**（元ファイルでは ⲯ）: III,5 `ⲛⲉ ⲝⲛⲏⲟⲩ`（ID 7505518、ⲛⲉⲥⲛⲏⲟⲩ か）、I,5 `ⲙⲡⲟⲩⲝⲟⲩⲱⲛ`（ID 7501992、ⲙⲡⲟⲩⲥⲟⲩⲱⲛ か）、V,3 `ⲟⲩⲥⲩⲝⲩⲅⲟⲥ`（ID 7506693、ⲥⲩⲍⲩⲅⲟⲥ か）。変えていない。
- **IX,1 の表題** `ⲙⲉⲗϫⲓⲥⲉⲇⲉⲕ`（ID 7511769）: ⲭ ではなく ϫ になっている。

- **意味を特定できないまま `[...]` にした残骸**: `ⲃϧ`（IX,3 ID 7512102、7512197）、単独の `ϧ`（II,1 ID 7503832、XI,2 ID 7512553）、`ϭ ϧ ϧϭ`（V,5 ID 7506987）。欠損注記の一種とみているが、内容は読み取れていない。

## 8. 再実行と検証

```
python3 scripts/build.py      Nag_Hammadi.txt  出力フォルダ
python3 scripts/verify.py     Nag_Hammadi.txt  出力フォルダ
python3 scripts/make_tei.py   出力フォルダ            # tei/ を作る（build.py のあとに実行）
python3 scripts/verify_tei.py 出力フォルダ [tei_all.rng]
```

標準ライブラリだけで動く（`verify_tei.py` に TEI のスキーマを渡して検証するときだけ `lxml` が要る）。`build.py` は同じフォルダの `restore.py` を読み込む。Python 3.9 と 3.13 で実行し、TEI を含めて出力が同一になることを確認した。

`verify.py` が確かめること:

1. 元の全トークンが「出力された／`[...]` に置き換えた／削除した」のどれか 1 つだけに当たる。
2. 出力と `changes.tsv` から元の各行を復元でき、ⲯ→ⲝ と記録された ⲍ・ⲯ の挿入以外は 1 文字も変わっていない。`build.py` の読み込み処理を使わずに元ファイルを読み直した文字列とも一致する。
3. 出力にある ⲍ・ⲯ はすべて `changes.tsv` に記録があり、その字を除くと元ファイルの綴りに戻る。`restored_letters.tsv` と `changes.tsv` が 1 対 1 に対応する。
4. 出力に ϧ、ラテン文字、数字、注記残骸、余分な空白が残っていない。
5. 文書別 TSV、TXT、`nhc_all.tsv`、`catalog.tsv` の内容と件数が互いに一致する。

出力や `changes.tsv` をわざと 1 か所書き換えた複製 12 通り（ⲯ を 1 字消す、記録にない ⲍ・ⲯ を入れる、本文の 1 字を替える、記録を 1 行消す、レコードや `[...]` を 1 つ消す、語の区切りを 1 か所つなぐ、など）で、どれも検証が失敗することも確かめた。

**復元を見直すとき。** 誤りが見つかった語は、`restore.py` の `RULES` からその行を消すか、条件（直前・直後の文字列、適用する文書や行 ID）を狭めて `build.py` を実行し直せばよい。足すときも同じ表に 1 行加える。

**元ファイルを作り直した場合。** 行 ID が同じで ⲍ・ⲯ・ⲝ が正しく入ったファイルなら、`build.py` と `verify.py` はそのまま使える。境目は ID と文字列で指定してあり、ⲍ か ⲝ を 1 つでも含むファイルに対しては、ⲯ→ⲝ の置換も ⲍ・ⲯ の復元も行わない。ⲝ を直し、今回戻した 744 語を元ファイルに書き戻した模擬ファイルで試し、56 単位・13,301 レコードの本文が今回の出力と 1 字も違わないことを確認した。角括弧や上線が入る形に作り直す場合は、境目の文字列と注記残骸の定義（`NOTE_PATTERNS`、`NOTE_SPECIALS`）を書き換える必要がある。

## 9. TEI ファイル

`tei/` に、文書ごとの TEI P5 ファイルが 56 個ある（計 7.9 MB。最大は `01-5_tripartite-tractate.xml` の 0.8 MB）。ファイル名は `tsv/`・`txt/` と同じで、中身は `nhc_all.tsv` と 1 対 1 に対応する。訳、語釈、品詞、レンマはまだ入っていない。

```xml
<text type="witness" xml:id="wit-II-6" n="NHC II,6" xml:lang="cop">
  <body>
    <div type="tractate" n="The Exegesis on the Soul" subtype="codexII">
      <head xml:lang="en">The Exegesis on the Soul — Nag Hammadi Codex II,6 (pp. 127,18–137,27)</head>
      <ab type="title">
        <s xml:id="II-7504565_17" n="1">
          <w>ⲧⲉⲝⲏⲅⲏⲥⲓⲥ</w>
          <w>ⲉⲧⲃⲉ</w>
          <w cert="high" resp="#zp">ⲧⲯⲩⲭⲏ</w>
        </s>
      </ab>
      <ab type="text">
        <s xml:id="II-7504566" n="3">
          …
```

| `nhc_all.tsv` | TEI |
|---|---|
| 文書（`unit`） | 1 ファイル。`<text type="witness" xml:id="wit-II-6" n="NHC II,6">` |
| レコード（`seq`） | `<s n="…">` |
| `kind` | `<s>` を包む `<ab type="…">`。同じ種類が続くレコードは 1 つの `<ab>` にまとめた |
| `src_id`・`src_tok` | `<s xml:id="…">`。行全体なら「写本番号-行 ID」（`II-7504566`）。行を分けたレコードには「_開始トークン位置」を付けた（`II-7504565_17`） |
| トークン | `<w>` |
| `[...]` | `<gap reason="lacuna" extent="unknown"/>`。注記の残骸から単位が分かるものには `unit` を付けた（`line` 253、`page` 4、なし 26） |
| ⲍ・ⲯ を戻した語 | `<w resp="#zp" cert="…">`。確度 A は `high`（702 語）、B は `medium`（42 語）。校訂本で確かめたら、この 2 つの属性を消せばよい |

**ヘッダー。** 題名（日・英・仏）、写本と頁・行（参考値）、方言、件数（`<extent>`）、`catalog.tsv` の注記、何をどう直したか（`<editorialDecl>`）を入れた。

- 題名はサイトの文書一覧（`scripts/build_site.py` の `CODICES`）と `data/catalog.xml` に合わせた。`catalog.tsv` の英題と違うものが 3 つある（V,1 Eugnostos、VI,2 The Thunder, Perfect Mind、XIII,2 On the Origin of the World (excerpt)）。
- 方言は、写本 I、X と XI,1–2 をリコポリス方言（準アクミーム方言）、ほかをサヒド方言とした。
- 下処理と TEI 化に生成 AI（Claude）を使ったことを `<projectDesc>` に書いてある。
- `<publicationStmt>` は「作業用ファイル（未公開）」とだけしてある。公開するときにライセンスの表記を入れてほしい。

**サイトの既存の本文ファイルとの関係。**

- 合わせた点: `<TEI xml:lang="cop">`、`<text type="witness" xml:id n>`、`<div type="tractate">`、`<s xml:id n>`、`<w>`、`<gap reason="lacuna" unit="line" extent="unknown"/>`、ID の形（既存の `III-7505191` と同じ）。
- 違う点: `<s>` を `<ab>` で包んだ。`<div>` の直下に `<s>` を置くと TEI P5 として妥当でなくなるため（既存の 2 ファイルは、tei_all で検証するとここで不適合になる）。検索ページとビュワーは `<text type="witness">` の子孫の `<s>`・`<w>` を読むので、動作には影響しない。
- `<w>` に `type`・`lemma`・`xml:lang="grc"` がないので、検索ページでは品詞が「未注」、レンマが語形そのままになる。`<phy>`、頁・行の印、訳もない。
- 証本の ID は `wit-II-6` のように文書ごとに分けた。既存の `wit-III`、`wit-V`、`wit-rep` とは重ならない。
- III,3 と VI,5 は、サイトに注釈つきの版（`data/eugnostos_tei.xml`、`data/republic_tei.xml`）がある。今回の 2 ファイルはそれを置き換えるものではない。III,3 の `<s>` の ID は既存の版と同じだが、冒頭（既存 `III-INCIPIT`、今回 `III-7505190_30`）と末尾（既存は `III-7505330` の 1 つ、今回は本文 `III-7505330_0` と奥書表題 `III-7505330_19`）が違う。
- V,1 は、既存の `eugnostos_tei.xml` では枠だけ（`wit-V`）になっている。本文は今回の `05-1_eugnostos.xml` にある。
- 並行する証本（『ヨハネのアポクリュフォン』II,1・III,1・IV,1 など）は 1 つにまとめず、別々のファイルにした。
- 番号: サイトの文書一覧は VI,8 を「書記による覚書」、VI,9 を「アスクレピオス」としているが、ここでは通用の番号に従い、覚書は VI,7 の末尾（`<ab type="colophon">`）、アスクレピオスは VI,8 としている。XI,2a–2e はサイトの一覧にない。I,1 は元ファイルにないので TEI もない。

**検証。** `scripts/verify_tei.py` で次を確かめた。

1. 整形式の XML で、UTF-8（BOM なし）・LF であること。
2. TEI から組み立て直した「通し番号、種類、行 ID と開始位置、本文」が `nhc_all.tsv` と完全に一致すること。
3. ⲍ・ⲯ を戻した語の印が `restored_letters.tsv` と 1 対 1 に対応し、印のない `<w>` に ⲍ・ⲯ がないこと。
4. `<s>` と証本の `xml:id` が、全ファイルを通じて重複しないこと。
5. ヘッダーの件数、本文の実数、`catalog.tsv` の件数が一致すること。
6. TEI P5 の RELAX NG スキーマ（tei_all.rng、P5 4.3.0）で、56 ファイルすべてが妥当であること。

このほか、サイトの `search.html` の読み込み関数（`parseText`）と、ビュワー（`republic.html`）の `buildFlow`・`phyGroups` をそのまま取り出して jsdom 上で実行し、56 ファイルのセグメント数・トークン数・欠損の数が `catalog.tsv` と合うことを確かめた。TEI をわざと 1 か所書き換えた複製 20 通り（`<w>` を消す・足す・つなぐ、復元の印を外す、`<gap>` を消す、ID を重複させる、など）で、`verify_tei.py` の検証が失敗することも確かめた。

**サイトで使うとき。** 検索ページは、`data/catalog.xml` の `<bibl type="document">` のうち `<ref type="xml" target="…"/>` を持つ文書を読み込む。TEI をリポジトリに置いて、文書ごとにこの項目を足せば、検索と統計に出る（全部足すと、読み込む XML が 7.9 MB 増える）。本文を表示するには、文書ごとのビュワー（HTML）が別に要る。
